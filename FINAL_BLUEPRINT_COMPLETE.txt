SECTION 2 — BILLING SNAPSHOT (IMMUTABLE)
========================================
Schema (add)
model BillingSnapshot {
  id             String        @id @default(cuid())
  roomNumber     String
  billingMonthId String
  billingMonth   BillingMonth  @relation(fields: [billingMonthId], references: [id])
  snapshotData   Json
  createdAt      DateTime      @default(now())
  createdBy      String
  @@unique([roomNumber, billingMonthId])
}

Behavior
- On first document generation (versionNo === 1):
  - Compose snapshot from BillingRecord + derived fields and write BillingSnapshot
  - Audit: DOCUMENT_GENERATE_SNAPSHOT with actor + payload
- Regenerate documents do NOT modify snapshot
- Rendering:
  - If snapshot exists (or month.closed), use snapshotData instead of live BillingRecord
- Analytics:
  - If month.closed, compute from snapshot only

Code Changes
- services/documents.ts:
  - When generating v1, upsert BillingSnapshot if not exists
  - Use snapshotData to render if exists or if month.closed
- services/analytics.ts:
  - Use BillingSnapshot for closed months

SECTION 4 — FINANCIAL COMPLETENESS
========================================
Schema (add)
model PaymentCredit {
  id             String   @id @default(cuid())
  residentId     String
  resident       Resident @relation(fields: [residentId], references: [id])
  amount         Decimal  @db.Decimal(12,2)
  createdAt      DateTime @default(now())
  sourcePaymentId String
  sourcePayment  Payment  @relation(fields: [sourcePaymentId], references: [id])
}

Behavior
- Overpay:
  - Create PaymentCredit for resident equal to overpay amount
- Auto-apply:
  - On new month or during match, if resident has credit, apply to current billing first (create PaymentMatch entries to represent applied credit) then consume credit (update remaining)
- Partial payment:
  - Continue supported; outstanding = billed - matched
- AuditLog:
  - PAYMENT_CREDIT_CREATE, PAYMENT_CREDIT_APPLY with before/after amounts

Code Changes
- payments.ts:
  - After computing sums, if existingPaymentSum + amount > payment.amount → allocate overpay into PaymentCredit
  - Utility to fetch resident from billingRecord.roomNumber via latest active RoomResident
- billing.ts / monthly processes:
  - When listing analytics or closing month, compute with matches + credits

Schema (add fields)

  - deletedBy String?

Middleware
- Prisma $use:

  - For soft delete: update deletedAt/deletedBy instead
